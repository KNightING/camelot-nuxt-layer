## Summary
將 nuxt 由 4.6.3 升級至 4.6.4(安全性釋出:8 項 Nuxt advisory,並帶入 nitropack 2.13.6 修正 3 項 Nitro advisory),README 範例範圍同步為 `^4.6.4`,並把傳遞依賴 `@nuxt/cli` 由 4.0.1 升至 4.0.3。
僅動依賴版本與 lockfile,無程式邏輯變更;lint、typecheck、build 通過,playground 啟動無 console 警告。來源:https://github.com/nuxt/nuxt/releases/tag/v4.6.4

## Cross-Repo Scope
無（單一 repo）

## Key Decisions
- **[Milestone]** 使用者選定 `4.6.4.0`(Patch+1,自 4.6.3.1 起算,與 nuxt 版本對齊);版本分支自 `main` 切出;非標準四段格式,跳過版本檔同步。
- **[行為變更盤點]** release notes 5 項行為變更對本 layer 無影響:`app/` 無 `createError`/`showError`/`useError`,`nuxt.config.ts` 無 `routeRules`/`workspaceDir`,dev server 為 Vite。
- **[執行中]** `@nuxt/cli` 4.0.1 搭配 nuxt 4.6.4 時 `nuxi dev` 啟動即崩潰(`options.hostname.toLowerCase is not a function`,`#syncAllowedHosts`);`pnpm update @nuxt/cli` 升至 4.0.3(其 changelog 為 allowedHosts 相關修正)後正常。只有一種合理作法,直接做並記於此。
- **[完成後]** commit + 開 PR(base 4.6.4.0)。

## Deviations
計畫原只列 `package.json`、`README.md`、`pnpm-lock.yaml`;執行中發現 dev server 崩潰,多升級傳遞依賴 `@nuxt/cli`(只影響 `pnpm-lock.yaml`,未新增檔案)。`pnpm test` 仍有 2 個既有失敗檔(Windows 路徑問題,`main` 上同樣失敗),與本計畫無關。
